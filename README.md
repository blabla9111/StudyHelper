# StudyHelper — цифровой деканат (концепт)

Личный кабинет студента, преподавателя и сотрудника деканата. Это учебный концепт для конкурса, **не официальный сервис вуза**. Все данные вымышленные.

Шаг 4 (текущая версия): вход с тремя ролями, профиль, список группы, колокольчик, расписание, зачётка и ведомости, раздел «Сообщения» и три функции по итогам опроса студентов:

1. **«Мой день»** (главная студента): лента карточек по важности. «Изменилось» с «было → стало» (время, аудитория, формат), кнопки «Добавить в календарь» (.ics), «Как дойти» и «Подключиться»; ближайшая пара с обратным отсчётом; дедлайны с отметкой «Сделано»; мини-трекер справок; адресные объявления деканата («Нужно действие» или «К сведению»); переключатель «Только важное».
2. **Карточка пары** (открывается из расписания и из ленты): материалы, запись (плеер-заглушка), задание и дедлайн, просьба записать пару и ответ преподавателя, формат «очно / онлайн / очно + трансляция» со ссылкой. Кнопка «Подключиться» активна за 15 минут до начала. Преподаватель управляет всем этим в той же карточке, а запросы на запись видит на экране «Записи».
3. **Справки**: каталог и поиск по ситуации («справка в военкомат»), форма с данными из профиля, трекер «Принята → Проверяется → Подписана → Готова», электронная справка в PDF с QR-кодом, страница проверки подлинности, очередь заявок у деканата и объявления деканата.

4. **Сообщения** (`/messages`): личные диалоги и чат группы без выхода в личные мессенджеры.
   - *Кто с кем:* студент пишет своим преподавателям, одногруппникам и в чат своей группы; преподаватель пишет студентам групп, у которых ведёт дисциплины, а также любым коллегам и деканату; деканат пишет любому студенту и любому преподавателю. Студент может ответить деканату в том же диалоге, но первым ему не пишет. Остальное запрещено на сервере.
   - *Чат группы* есть только у студентов группы: преподаватели и деканат его не видят и открыть не могут (404).
   - *Рассылка преподавателя:* выбор групп, текст, окно подтверждения «Отправить N студентам?». Каждый студент получает копию в личном диалоге с преподавателем с пометкой «Рассылка · группа» и уведомление; ответ студента видит только преподаватель. Не больше 5 рассылок в час, удалить рассылку у всех можно в течение 5 минут. История — в блоке «Мои рассылки».
   - *Непрочитанные:* счётчики в списке и значок у пункта меню; новые сообщения приходят без перезагрузки (опрос раз в 5 секунд в открытом диалоге и раз в 30 секунд в списке, только пока вкладка активна). Уведомление в колокольчик: при первом сообщении и затем не чаще раза в 10 минут; чат группы без уведомлений.
   - *Ограничения:* только обычный текст до 2000 символов, не больше 20 сообщений в минуту, свои сообщения можно удалить в течение 5 минут. Файлов, голосовых, реакций и ботов нет.

**Как это работает вместе.** Любое изменение (перенос, смена формата, новый дедлайн, ответ на запрос записи, смена статуса справки) пишет уведомление в колокольчик, попадает в карточку пары и в «Мой день».

## Проверка на телефоне

Режим `npm run dev` с телефона по адресу компьютера не работает (Next.js блокирует такие запросы). Для проверки на телефоне, подключённом к той же Wi-Fi сети:

```
npm run build
npm start
```

Затем откройте на телефоне `http://<IP-компьютера>:3000` (IP показывает команда `ipconfig`, строка «IPv4-адрес»). Если Windows спросит про брандмауэр, разрешите доступ для частной сети. Быстро посмотреть мобильный вид можно и на компьютере: в Chrome нажмите F12, затем значок телефона и выберите ширину 360 px.

## Полезные команды

| Команда | Что делает |
|---|---|
| `npm run dev` | запуск для разработки |
| `npm run build` и `npm start` | сборка и запуск «как на сервере» |
| `npm run seed` | сбросить данные и заполнить заново |
| `npm run typecheck` | проверка типов |
| `npm run check:security` | автопроверка защиты, 170+ проверок: доступы, запреты, лимиты, журнал (сайт должен быть запущен) |
| `npm run check:messages` | сквозная проверка сообщений: диалоги, чат группы, рассылка, уведомления, лимиты (10 групп проверок). Меняет данные и лимиты в памяти сервера: после неё `npm run seed` и перезапуск сайта |
| `npm run check:features` | сквозная проверка «Моего дня», карточки пары, справок и объявлений (14 сценариев). Меняет данные, после неё `npm run seed` |
| `npm run check:flows` | сквозная проверка: замена пары, ввод баллов, закрытие ведомости. Меняет данные, после неё выполните `npm run seed` |

## Если что-то не работает

- **Порт 3000 занят:** `npm run dev -- -p 3001`, адрес http://localhost:3001
- **Ошибка при `npm install` про better-sqlite3:** проверьте версию командой `node -v` (нужна 22 или новее), при необходимости переустановите Node.js и повторите.
- **Ошибка «Module not found» про `pdf-lib`, `qrcode` или `@pdf-lib/fontkit`:** после обновления проекта не выполнен `npm install`. Остановите сайт (Ctrl+C), выполните `npm install` и запустите снова. Пока пакеты не установлены, кнопка «Скачать PDF» отдаёт запасной образец справки (файл `assets/demo-certificate.pdf`) с припиской `-obrazets` в имени, а остальной сайт работает.
- **После обновления проекта не видно новых кнопок или демо-данных:** остановите сайт (Ctrl+C), удалите папку `.next`, выполните `npm install`, затем `npm run dev` (для `npm start` сначала `npm run build`). Версия демо-данных поднялась, база обновится сама при запуске (все изменения в ней сбросятся).
- **Нужно вернуть демо-данные:** `npm run seed`

## Настройки запуска
Все настройки описаны в `.env.example`. Скопируйте его в `.env` и подправьте.

| Настройка | Что делает |
|---|---|
| `DEMO_MODE` | `true` показывает блок с демо-аккаунтами на странице входа, `false` скрывает его всегда (сильнее, чем `NEXT_PUBLIC_DEMO`). Без настройки: виден при `npm run dev`, скрыт при `npm start` |
| `ALLOW_DEMO_SEED` | В боевом режиме (`npm start`) демо-аккаунты не создаются и сид не сбрасывает данные, пока не задано `true`. Нужно только для показа на конкурсе, после него уберите |
| `COOKIE_SECURE` | Cookie сессии с флагом `Secure` включён сам в боевом режиме. **Для проверки на своём компьютере по `http://localhost` через `npm start` поставьте `COOKIE_SECURE=false`, иначе войти не получится.** На сайте с HTTPS настройку не задавайте |
| `PUBLIC_BASE_URL` | Настоящий адрес сайта (`https://studyhelper-demo.ru`). Проверка Origin и QR-коды в справках привязаны к нему. При запуске без него сервер пишет предупреждение |
| `TRUSTED_PROXY_HOPS` | Сколько прокси стоит перед приложением (по умолчанию 1). Адрес клиента для лимитов берётся из `X-Forwarded-For` с конца цепочки; прокси обязан перезаписывать этот заголовок (Caddy делает это сам, в nginx `proxy_set_header X-Forwarded-For $remote_addr;`) |
| `CSP_REPORT_ONLY` | `true` переводит политику безопасности контента в режим «только сообщать» |

Ограничения: вход блокируется после 5 неудач на пару «логин + адрес» (и после 30 по одному логину с любых адресов), тело запроса не больше 64 КБ, справки, запросы на запись, PDF и поиск адресатов ограничены по числу действий в минуту на пользователя. Открытие закрытой ведомости и правка баллов после этого пишутся в таблицу `audit_log`, деканат получает уведомление.

## Недавние изменения
- Справки: вкладки «Актуальные» и «Архив» (готовые и отклонённые заявки старше месяца).
- Список группы: кнопка «Написать» у каждого одногруппника.
- Расписание: без списка сегодняшних пар внизу (он на главной).
- «Запросы на запись»: одна пара — одна карточка с таблицей студентов и причин и общим ответом.

## Устройство

- Next.js 16 (React 19, TypeScript), Tailwind CSS 4, шрифт Inter (лицензия OFL), иконки Lucide (лицензия ISC).
- База SQLite (`data/studyhelper.db`), создаётся автоматически. Для большой нагрузки схема переносится на PostgreSQL.
- Пароли хранятся только как bcrypt-хеши. Сессия — случайный токен в httpOnly-cookie, в базе лежит только его хеш.
- Данные пользователя всегда выбираются по id из сессии, а не из адреса страницы, поэтому чужой профиль, группу или уведомления открыть нельзя.
- Файл `.env.example` описывает настройки сервера; ключей и паролей сервисов в коде нет.
