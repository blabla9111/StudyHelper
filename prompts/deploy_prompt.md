## О проекте (читай перед работой: `README.md`, `CLAUDE.md`, `PROCESS.md`, `.env.example`, `next.config.ts`, `package.json`)
- Next.js 16 (App Router, React 19, TypeScript), Node 22. Один процесс, без отдельных сервисов.
- База: SQLite через `better-sqlite3` (нативный модуль, нужна сборка под ту же ОС и версию Node, что на сервере). Файл по пути `DATABASE_PATH` (по умолчанию `./data/studyhelper.db`). Режим WAL, рядом появляются файлы `-wal` и `-shm`.
- Запуск: `npm start = tsx scripts/seed.ts --if-empty && next start`. Демо-данные заполняются только в пустую базу; `npm run seed` стирает всё и пересоздаёт (на сервере без моего подтверждения не запускать).
- Настройки только через переменные окружения: `DATABASE_PATH`, `DEMO_MODE`, `COOKIE_SECURE`, `PUBLIC_BASE_URL`. Позже появится ключ ИИ-помощника: он живёт только на сервере (переменная окружения), не в коде, не в образе и не в репозитории.
- PDF-справки читают шрифты из `assets/fonts` и запасной файл `assets/demo-certificate.pdf`: эти папки должны попасть в образ.
- Защита от CSRF сравнивает заголовок `Origin` с `x-forwarded-host` или `host`. За обратным прокси прокси обязан передавать исходный `Host` / `X-Forwarded-Host`, иначе все POST вернут ошибку.
- Ограничения частоты запросов хранятся в памяти процесса и берут IP из `X-Forwarded-For`: запускать ровно один экземпляр; прокси должен подставлять настоящий IP клиента (и не принимать этот заголовок извне как есть).
- Все данные вымышленные, на сайте есть плашка «учебный концепт для конкурса». Не убирай её.

## Правила безопасности
- Секреты (пароли, ключи, `.env`, приватные SSH-ключи) не вставляй в чат, не клади в репозиторий и образ, не печатай в логах. Если я случайно прислала секрет, скажи, что его нужно сменить.
- Вход на сервер только по SSH-ключу, пароль root отключить. Не открывай наружу порт приложения, только прокси.
- На конкурсном стенде `DEMO_MODE=true` (жюри должно видеть демо-аккаунты), `COOKIE_SECURE=true`, `PUBLIC_BASE_URL` с настоящим адресом. Объясни мне, что после конкурса нужно поставить `DEMO_MODE=false` и сменить пароли.
- Данные только вымышленные. Если увидишь в проекте что-то, похожее на реальные персональные данные, остановись и скажи мне.
- Разрушающие действия (удаление тома или базы, `npm run seed` на боевом сервере, перезапись `.env`, смена правил брандмауэра, которая может закрыть мне доступ по SSH) делай только после моего явного «да» и после копии базы.
- Ничего не придумывай про мой сервер: если не знаешь версию ОС или провайдера, спроси или дай команду, которая это покажет.
- Не меняй код приложения без необходимости. Если для деплоя нужна правка кода (например, проверка `/healthz`), покажи её отдельно и объясни, зачем.
