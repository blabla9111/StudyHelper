```bash

```

## C. Cookie с флагом Secure

Способ 1, в браузере: войдите, нажмите `F12` → вкладка **Application** (Chrome/Edge: «Приложение») → **Cookies** → ваш адрес → строка `sh_session`. Должны быть отмечены **Secure** и **HttpOnly**, SameSite = Lax.

Способ 2, на сервере (по SSH):

```bash
curl -si -X POST https://ВАШ.ДОМЕН/api/auth/login \
  -H 'Origin: https://ВАШ.ДОМЕН' -H 'Content-Type: application/json' \
  -d '{"login":"student1","password":"Study-One-26"}' | grep -i '^set-cookie'
```

- [ ] В строке `set-cookie` есть `Secure`, `HttpOnly`, `SameSite=lax`.

## I. Необязательно: прокси не даёт подделать IP

Проверяет, что подмена `X-Forwarded-For` снаружи не обходит ограничение попыток входа. Побочный эффект: ваш IP на 10 минут получит блокировку входа, поэтому в конце перезапуск контейнера.

**На моём компьютере, в Git Bash/WSL или на сервере (по SSH):**

```bash
for i in $(seq 1 35); do
  curl -s -o /dev/null -w "%{http_code} " -X POST https://ВАШ.ДОМЕН/api/auth/login \
    -H "X-Forwarded-For: 10.9.8.$i" -H 'Origin: https://ВАШ.ДОМЕН' -H 'Content-Type: application/json' \
    -d "{\"login\":\"probe$i\",\"password\":\"x\"}"
done; echo
docker compose restart app   # только на сервере: снимает блокировку
```

- [ ] Среди ответов появились `429` (около 31-й попытки). Если все ответы `401`, значит прокси пропускает подделанный заголовок: не сдавайте стенд, пришлите вывод.

## Чего НЕ делать на боевом сервере

- `npm run seed` и `check:flows`/`check:features`/`check:messages`: они меняют или стирают данные. Автопроверки гоняются только на тестовой копии.
- Удалять том `studyhelper-data` или перезаписывать `.env` без свежей копии.
- Открывать порт 3000 в брандмауэре.
